# 1.3.0 测试记录

> 这是 1.3.0 的早期记录。当时的菜单和音效与现在有所不同，当前用法请看[使用说明](使用说明.md)，版本变化见[更新记录](迭代记录.md)。

这一版加入多组照片合片、特写、音乐卡点和飞机试验模式。

## 建议试用顺序

1. 导入两段中途松开快门的鸟类连拍：分别试「一组」和「多组」，勾选要合片的组；切换单组再返回，核对排序、速度、总时长和已编辑内容。
2. 在输出中分别启用鸟眼、鸟头、鸟身；独立换颜色，调整鸟身大小。开启快门边框，试颜色、大小和低频闪烁，再将上限设为120。30fps视频无法呈现120次独立闪烁，界面保留采样提示。
3. 添加索尼10fps/30fps显示档和尼康Z8快门，再添加背景音乐。确认60/120内置档已移除。索尼30显示档沿用原20档录音，不变速；两种索尼声音及Z8都循环使用当时提供的录音。
4. 多轨分别调整音量、起点、素材偏移、长度、静音、循环及淡入淡出，试听并导出；留意短非循环声音在设定时刻进入，结束后的静音正常。
5. 选择照片建立特写，替换一段原时段，调整秒数、缩放、横纵构图、动态边框和颜色。尝试重复创建、重叠范围以及删除后恢复，提示和总时长应合理。
6. 使用节奏明显的音乐生成节拍/能量高潮建议，选择清晰度/展开程度较好的画面候选，对齐后试听，按实际听感调整。
7. 导入飞机照片前选择「飞机（试验）」。检查机头和含机翼机身分别识别、配色、大小与快门模拟；构图有机头居中、全机留白等预置。在原图中逐帧检查并「修正机头」，修正仅约束当前帧。两类设置和识别编辑分别保存，切换中取消应恢复上一份分析。
8. 导出一次H.264与HEVC；重新打开软件检查偏好。重要编辑保存在分析缓存，清空缓存会删除编辑，目前未提供可迁移的独立工程文件。

## 已完成的本地验证

- Swift 39项、Mac与Windows Python各56项、打包资源5项检查通过。
- Mac通用包含两种架构，镜像校验、只读挂载后资源和临时签名通过；隔离设置/缓存的实际窗口完成32张受控飞机照片分析，进度步骤和飞机控件正确。
- Mac原生应用状态流程及Windows 1.3.0冻结成品：两组8张受控飞机、8张机头/0眼框、替换特写后16帧；取消切换恢复、两类设置重启、修正和特写缓存、H.264导出通过。
- Windows 1.3.0成品：自检/启动、80次布局、12张鸟类两组/34帧特写合片、音乐对齐和缓存兼容、双轨H.264/HEVC导出通过。短音轨20轮PCM与最终AAC起点/静音通过。
- 成品权重、许可、音效与压缩包完整性已核对。菜单仅有索尼10/30显示档及Z8三项；60/120派生选项和派生声音不分发，原始录音归档仍保留。Windows空data目录用于便携模式，没有测试偏好或照片。

## 必须了解的范围

- 飞机已接入独立开源部位网络及图像跟踪，鸟类模型保持原样。独立样例仍有倒置双翼机错到翼尖的失败，遮挡、小目标、复杂角度均需检查。开发中的两组/位移测试是同一照片的受控变换，真实飞机连拍还需要单独测试。
- 飞机首次分析较慢且内存较高，Mac完整测试进程峰值约3.53GB；部位模型用CPU，同一应用内飞机任务排队。取消需等待正在运行的一次推理返回；低内存Mac尚未验证。
- Windows是在Parallels Windows ARM中运行x64成品并回退CPU测试，不能代替实体x64显卡/硬件编码验证。
- Mac包支持Apple芯片/Intel两种架构、最低macOS14，目前仅本机Apple芯片实际运行。仍使用临时签名；原用户UTF-8无法打开的问题未复现，原因仍待查。请受影响用户复测，不要用文本编辑器打开包内可执行文件。
- 输入只包括照片，软件内多组合片不添加外部视频片段。
