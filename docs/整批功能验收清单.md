# 1.4 测试记录与复测方法

[1.5.0 测试版](https://github.com/cyandee/BirdLock/releases/tag/v1.5.0-beta.1)已提供双平台安装包及签名更新文件。这页保留各轮测试结果，也列了一些可以自己复测的步骤。如果你遇到不同结果，欢迎告诉我。

## 1.4.0 已测情况

- Swift 44 项、Mac 和 Windows 的 Python 测试各 62 项、资源及分发检查 11 项通过。
- 两端测过照片导入、分组排序、手动修正、排除、缓存恢复、特写、音效菜单和赞赏页。
- Windows 成品做过 80 次布局检查、H.264 / HEVC 导出，以及 20 轮短音频起点和尾部静音检查。
- Mac 通用 DMG 的镜像、包内签名和复制安装后的签名检查通过。发布的四个文件大小及 SHA256 已与 GitHub 端核对。

这些是本地结果。标签触发的云端自动构建失败，原因见[构建说明](构建与发布.md)，下载页没有使用那次构建的产物。

## 可以这样复测

准备两组连拍照片，最好既有同一只鸟的连续动作，也有不同拍摄速度的组。再准备一首自己有权使用的音乐；测试清缓存前请先保存需要的成片。

| 功能 | 检查方法 |
|---|---|
| 对焦框 | 分别打开眼、头、身，设不同颜色。缩放鸟身框，确认眼和头的大小不跟着变化；检测完整时应包含展开翅膀。对照预览和导出。 |
| 快门闪烁 | 改大小、颜色，先试 1 或 6 次/秒，再试 120；重开检查设置。高频受输出帧率限制，可能看起来静止或变慢。 |
| 导入与合并 | 同一批照片分别按一组和多组导入；合并后切回单组再返回，检查顺序、各组速度和总时长，组边界不应混入补帧。 |
| 片段排序 | 给照片加修正、排除和特写，再上移/下移组，检查这些编辑是否跟着照片。跨组特写要先缩小到单组内。排序后裁剪会恢复全部，音轨仍按秒定位，需要重新试听。 |
| 替换特写 | 用第 4—5 张做特写，调整时长、缩放、横纵构图、框和颜色。删除后恢复原照片；特写不能重叠，被排除的起始照片不会强行加入成片。 |
| 特写边界 | 起点移到原终点后，终点应跟着后移。重复或重叠设置给出提示，并保留原有设置。 |
| 单张快门声 | 新特写开始时响一次，延长停留时间不循环；关闭、调音量有效。倒放、重复和排序后检查触发位置；旧特写默认无声。 |
| 相机菜单 | 一级选相机，二级选档位：A1 II 5/10/15/20/30、A9 III 60/120、A7 V Hi+30/Mid15、Z8 20，A7R VI 原录音。旧 A1 选择能迁移，缺失声音会提示。 |
| 多轨 | 快门与背景音乐同时播放，分别静音、调起点、长度、素材偏移、循环和淡入淡出。测试短音频结束后的静音，以及暂停续播和实际导出。 |
| 音乐卡点 | 选音乐候选与画面候选，对齐后试听。被特写替换的照片应定位到特写；已裁掉的照片不能对齐，静音片段不应给出虚假节拍。 |
| 缓存 | 重新打开同一组照片、切换单组或升级旧缓存，检查修正、排除和特写是否保留。清缓存会删除这些编辑，确认框默认取消。 |
| 飞机 | 在真实连拍里逐帧检查机头与机身，尝试修正、切换、取消和导出。重点看侧面、正面、斜视、小目标和遮挡。 |
| Mac | 从完整 DMG 复制安装，测试中文路径；遇到原 UTF-8 报错时记录环境。大倍率鸟身框导出不应异常增加位图大小或在边缘画假框。 |
| Windows | 重复导入、切页、缩放窗口、播放、导出和关闭；测试中断后恢复、高 DPI、实体显卡和软件编码回退。 |
| 联系和支持 | 帮助、关于和复制邮箱均为 cyanodee@gmail.com。咖啡页由用户主动打开，二维码完整，能关闭，所有功能免费。 |

## 还缺哪些测试

实体 Intel Mac、不同 Windows 显卡、低内存设备，以及真实飞机连拍还需要补测。当前 Windows 回归使用过 Parallels 的 ARM 系统运行 x64 程序，显卡回退 CPU，结果不一定代表实体显卡。

飞机的受控位移测试只验证跟踪，无法说明最初找的机头一定正确，倒置双翼机已出现翼尖误判。Mac 旧的 UTF-8 启动报错尚未复现，当前也没有 Apple 公证。

反馈时请带上系统、软件版本、照片数量、操作步骤，以及问题出现在预览还是导出。截图中可以遮住私人目录和账号，邮箱：cyanodee@gmail.com。

## 1.4.1 本地修复测试

这一版重点复测取消视频导出后的恢复：在同一进程里点取消、换编码再导出，关闭导出窗口后重试，再导入另一组照片继续导出；同时检查 GIF、图片序列和旧目标文件是否保留。

编码器探测、阻塞管道、解码异常、多线程缓存与缓存缺失也加入了自动检查。实际 NVIDIA 显卡上的取消和分析速度，还需要鸟友用原设备、原照片复测。

性能测试分开记录：首次鸟类分析、重开缓存、飞机跟踪和机头模型推理。局部步骤变快不代表整组分析按同样比例变快。鸟类首次分析目前没有测出明确改善。

当前本地结果：Swift 44 项、Mac/Windows 的 Python 各 82 项、资源检查 11 项通过。最终 Windows 成品两次取消约 0.17 / 0.19 秒退出，之后换 HEVC、重新导入另一组导出 H.264、GIF 和图片序列均通过；旧目标文件保留，20 轮短音频与 AAC 检查通过。同轮较早候选还完成了 80 次布局和两种尺寸的编码回归。实际 NVIDIA 设备上的表现仍待复测。

## 1.4.2 本地修复测试

这一版重点测试「在界面上换编码/质量后立即导出」，包括还没导出过就换、导出后再换，以及取消后换。H.264、HEVC、ProRes 422 HQ、ProRes 4444 都要在同一进程内完成，不能只给内部变量赋值。

Mac 需要在原 M1 Max/macOS 15.5 上打开光流复测；同时检查不可用、辅助进程异常和超时时，主程序能否继续并显示帧混合提示。当前本机 1280×720 实际光流视频导出通过，原机崩溃仍需要完整 ips 和导出设置核对。

两端检查帮助菜单导出 ZIP、脱敏内容和独立赞赏入口。诊断 ZIP 不应包含照片、音频或设置；二维码完整，赞赏不影响功能。高分辨率色彩转换按 4320×5760 验证输出一致和并发稳定性。

本轮本地 Python 两端各 89 项、Swift 50 项通过。Windows 冻结成品四种编码真实控件切换、两种取消、HEVC 重试、新组 H.264、GIF、图片序列、短音频 PCM/AAC 和日志 ZIP 均通过；Mac 原生界面日志导出和赞赏入口已实际操作验证。原 NVIDIA 与 M1 Max 设备仍需复测。

## 1.4.3 · 600 源帧长序列补测

针对 2K、30 fps、约 600 张照片的反馈，增加横向 2560×1440 和竖向 1440×2560 对照。测试使用 12 张 8640×5760 样例循环组成 600 个独立源索引，源 20 fps、输出 30 fps，确保实际产生 599 次光流插帧；每段输出 899 帧，均完整解码通过，没有触发回退。重复样例用于压力测试，不能替代用户原片或 M1 Max/macOS 15.5 的验证。

| 本机受控样例 | 1.4.2 RSS 峰值合计 | 1.4.3 RSS 峰值合计 | 光流导出耗时 |
| --- | --- | --- | --- |
| 横向 2K | 7.26 GiB | 4.61 GiB | 68.5 → 69.4 秒 |
| 竖向 2K | 14.65 GiB | 2.93 GiB | 63.8 → 73.2 秒 |

RSS 为主程序与直接辅助进程之和，不含单独核算的 GPU、系统服务内存，也不代表原电脑的用量。本机为 Mac17,9/macOS 27.0.1；上表是单次受控对照，性能会随设备和原片变化。1.4.3 每组测试启动 10 个顺次回收的辅助进程，时间线、帧数和输出尺寸保持一致。

额外比较了解码后的画面：不补帧的横向 SSIM 为 1，其他对照约 0.987—0.992，并非逐像素一致；抽看插帧与回收边界，旧、新版本都能看到快速翅膀的重影。这里验收长序列稳定性与内存回收，插帧观感仍需原片确认，不把可导出当成画质完美。

Swift 52 项、Mac/Windows Python 各 89 项通过。Windows 同步版本号并完成成品导出回归，功能沿用 1.4.2。


## 1.4.4 · Mac AI 光流明暗交替

补充灰阶、彩色色块和运动前景的背景一致性回归。相同静止图像通过旧实现时，中灰 128 会变成 146；新实现与写入使用相同的显式色彩空间读回，补帧不再额外变亮。两项新增测试在修复前失败，修复后 Swift 共 54 项通过；包与分发测试 11 项通过。

同一组 53 张原片、1920×1080 / 30 fps / 0.5 速，导出 105 帧，实际 52 次光流。HEVC、H.264、ProRes 422 HQ 的 AI 导出均完整解码、没有回退，重复帧和帧混合对照也通过。固定背景区域的补帧亮度偏差中位数，HEVC 修复前约 +13.78，修复后约 -0.08（0—255）；这是这组样例的测量，不能当作所有场景的画质保证。

另将这组照片循环三次组成 159 条源索引，在 2560×1440 / 30 fps 输出 317 帧，实际 158 次光流、3 个顺次处理进程、2 次预算回收。回收边界的背景亮度没有突跳，没有回退，完整解码通过。重复索引用于检查回收，不能当作更多原片或原 M1 Max 的测试。

最终 Mac 包内的实际光流程序另测 3 次独立启动、每次 3 个插帧相位，灰阶和彩色块中心读回误差为 0；镜像、包内签名和复制安装后的签名完整性通过。这一轮只修复 Mac 光流；修复现已随 1.5.0 双平台包发布。

- Swift 54 项、分发/签名准备脚本 19 项通过，包含此前光流颜色修复。最终 Mac 通用包和镜像完成签名、资源及复制安装校验，包内光流 helper 的三次独立灰阶/彩色测试通过。

- Mac 用独立 bundleID 的小型验证应用、实际 AppUpdater 和 Sparkle 做 1.5.0→1.5.1 安装重启：增量成功、损坏增量转完整包成功、篡改清单被拒绝。传输在测试进程中模拟 HTTPS 响应，没有修改系统证书或线上服务。此项是更新集成验证，不把小程序当作完整 BirdLock 升级证明。
- Windows 独立进程验证覆盖完整与增量安装、增量基础变化后的完整下载、签名/下载损坏拒绝、新版不能启动和45秒启动超时回退；设置与程序外文件原位置保留。网络层另测续传、忽略 Range、错误 Content-Range、取消、镜像、磁盘不足和非 HTTPS 拒绝。

1.5.0 更新源已开放。完整 BirdLock 在真实网络下跨版本更新，以及 Apple Developer ID / 公证后的分发，仍需继续验证；不能据本地模拟网络测试保证所有防火墙、杀毒软件或旧系统都可用。断电或强杀进程可能需要手动恢复，旧目录和完整包均保留。

最终 Windows 94 项单元与界面测试通过，原生更新器 42 项（含 Python→C# 的真实 RSA/UTF-8 签名互验）和 7 项安装进程测试通过。Mac 新增框架落盘约 2.8 MiB，Windows 更新器为 29,184 字节；它们是本次实测组件大小，不是以后每次更新的流量承诺。
