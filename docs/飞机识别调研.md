# 飞机识别



飞机模式目前还是试验功能。导入前选择「飞机（试验）」，就可以识别机身和机头，调整两种框的大小、颜色，保留快门闪烁，也能做特写和导出视频。

机头在倒置、遮挡、小目标或复杂背景下可能找错。我建议先切到「原图+识别」逐帧看一下，有偏差就用「修正机头」调整。鸟类和飞机分别保存构图、输出设置及识别缓存。

## 用了什么模型



机身沿用 YOLO11m 的 COCO airplane 类别（4），机头另用 [Grounding DINO tiny](https://huggingface.co/IDEA-Research/grounding-dino-tiny) 的 [ONNX Community 转换版本](https://huggingface.co/onnx-community/grounding-dino-tiny-ONNX)。鸟类仍使用原来的检测和姿态模型。

Grounding DINO 是通用的文字区域检测模型，并非专门训练的飞机机头模型。程序先用不同方向的查询定位，再结合图像跟踪保持前后帧的位置；结果互相冲突时会重新检测，缺测时不画机头框。分组切换后会重新定位。

约 204 MB 的量化权重、固定版本、查询参数和 SHA256 在[模型清单](../SharedResources/AircraftModels/manifest.json)中。两个模型页标注 Apache-2.0，安装包附模型和 ONNX Runtime 的许可与第三方声明。

## 目前测到的情况



静态样例试过侧面和斜视客机、正面螺旋桨飞机、远处小飞机及双翼机。其中倒置双翼机出现过把翼尖当机头的问题，多方向检测也没能排除。

跟踪测试把单张照片做受控位移，生成 32 帧序列；相对起始检测位置的误差约为 0.075—0.10 个代理图像像素。这个数字只说明跟踪能否跟住初始位置，初始位置找错了，仍然可能一路跟错。真实飞机连拍还需要继续测试。

两端应用已经测过分组、设置切换、取消、手动修正、特写、缓存和 H.264 导出。机身框偶尔会在整机与机翼之间变化，最后仍需要检查成片。

## 速度和内存



机头模型使用 CPU，同一应用里排队分析，取消时需要等当前一次推理结束。Mac 完整测试进程峰值约 3.53 GB，内存较小的电脑可能会比较吃力。

实体 Intel Mac、不同 Windows 显卡和低内存设备还需要更多测试。测试中使用过 Parallels Windows ARM 的 x64 模拟和 CPU 回退，实际显卡表现可能不同。

|---|---|

| 卫星飞机检测、机型分类 | 输出不包含需要的机头位置 |
