# 飞机识别：实现、验证与限制

更新日期2026-10-19，适用于1.4源码。「飞机（试验）」已在双平台接入自动机头/机身、序列跟踪、独立设置/缓存、构图、手动修正、预览与视频导出；保留快门模拟。机身检测和机头定位是不同任务，不用机身框中心冒充机头。

## 现行路线

1. 保留现有YOLO11m COCO检测器，显式选择airplane类别4取得机身候选；不更换鸟模型，也不对飞机加载鸟姿态模型。
2. 独立机头定位使用[IDEA-Research Grounding DINO tiny](https://huggingface.co/IDEA-Research/grounding-dino-tiny)的[ONNX Community转换](https://huggingface.co/onnx-community/grounding-dino-tiny-ONNX)。固定版本、约204MB量化权重、SHA256、查询词和输入参数见[模型清单](../SharedResources/AircraftModels/manifest.json)。模型页标注Apache-2.0，随包保留对应许可及ONNX Runtime MIT/完整第三方声明。
3. 这是通用文字区域检测器，没有专门针对飞机机头地标微调。通过多方向语义查询、一致性和局部图像跟踪保留序列锚点；不把一致性当作语义正确保证。
4. 语义种子后使用双向亚像素跟踪，比较局部图像搜索与机身提示；冲突交回语义重检。组边界独立重置，失败缺测不伪造结果；取消/结束释放独立会话。
5. Mac使用独立ONNX Runtime Swift库与串行分析队列；Python使用独立CPU部位推理。先结束机身检测器作用域，再进入大模型阶段，避免多任务同时持有多份资源。

## 验证覆盖

- 静态公开样例覆盖客机侧面/斜视、正面螺旋桨、远处小飞机和双翼机；测试图片不收入软件或源码。
- 对单张照片施加受控位移形成两组序列，验证组间重置、双向跟踪、缺测/重试、取消、缓存与绘制/导出。32帧完整链路的相对种子位移误差约0.075—0.10代理像素，**只反映相对自身模型种子的跟踪，不是机头语义精度**。
- 双平台应用流程验证两组8张、机头/机身控件、独立偏好重启、手动修正/特写缓存、取消恢复和实际H264导出；1.4再验证排序后照片编辑跟随。
- Mac完整分析/导出测试进程峰值约3.53GB；不能以独立模型探针的较低内存数字代替整应用峰值，也不承诺所有内存即时退还系统。

## 已知限制

- 倒置双翼机可把翼尖误认为机头；多方向一致也可能共同误判。小目标、遮挡、复杂背景与异常角度可能缺测或跳动。
- 机身检测框可能在整机/机翼之间波动；序列跟踪已加入冲突重检，仍需检查最终机头与机身是否合理。
- 尚缺独立标注的真实飞机连拍测试集，不能宣称所有视角或机型达到稳定语义精度。
- 低内存Mac、实体Intel Mac与Windows实体显卡需补测；Parallels中的CPU回退不替代显卡验收。
- 用户应在原图逐帧检查，可使用「修正机头」约束当前帧；飞机不显示鸟眼框，不把手动定位伪称自动检测成功。

## 历史调研与排除方案

| 路线 | 结论 |
|---|---|
| [StarMap](https://github.com/xingyizhou/StarMap) | GPL-3.0仓库；调研时官方权重链接返回404、旧PyTorch环境，未取得可验证权重，不分发 |
| [CALDN](https://github.com/HuaYuuu/CALDN-pytorch-release) | 飞机地标路线；调研时未取得可验证权重、许可未明确，不分发 |
| [Roboflow飞机头尾数据集](https://universe.roboflow.com/airplane-knk4v/airplane-nose-tail-detection) | 调研时无可验证模型权重；仅作未来训练线索，不调用在线推理 |
| DINOv2特征匹配、颜色/轮廓/主轴启发式 | 小目标和复杂视角不稳定，不作为机头识别替代品 |
| 卫星飞机检测、机型分类 | 不输出经验证机头地标，不冒充机头模型 |

历史调研中的“尚未启用飞机模式”仅代表原型阶段，当前实现和限制以上述1.4状态为准。构建入口、固定权重和完整许可见[模型资源说明](../SharedResources/AircraftModels/README.md)，验收见[功能清单](整批功能验收清单.md)。
