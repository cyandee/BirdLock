# BirdLock 1.4 构建、验证与发布

更新日期2026-10-19。维护者已明确批准发布安装包；[v1.4.0-beta.1测试版](https://github.com/cyandee/BirdLock/releases/tag/v1.4.0-beta.1)统一提供两平台、公开源码及校验值。固定正式版下载入口、Vercel配置与Apple正式分发后续处理。

## 版本与资源

根目录[VERSION](../VERSION)是双平台唯一版本来源，当前1.4.0，采用`major.minor.patch`；显式版本参数必须匹配。正式标签可用`v1.4.0`，测试标签可用`v1.4.0-beta.1`，应用内数字版本仍为1.4.0。

- 原有鸟类Core ML / ONNX模型保留，不替换为训练实验资源。
- [音效清单](../SharedResources/Audio/library.json)记录12项音效、相机、档位、来源和SHA256；旧派生录音与维护者上传归档在本地保留，不上传开发归档。赞赏图在SharedResources/Support，构建时复制、校验，不自动发起付款。
- 飞机约204MB固定权重不提交普通Git。`python scripts/fetch_aircraft_model.py`按[manifest](../SharedResources/AircraftModels/manifest.json)取得并核对版本、大小与SHA256；可用`--source-file <文件>`复用下载。有效文件复用，不匹配时保留并报错，不静默覆盖。
- `BirdLockAircraftRuntime`使用微软官方ONNX Runtime Swift1.24.2固定源码提交，Package.resolved随源码保留；首次SwiftPM解析需取得官方依赖和二进制，离线构建应预先准备缓存。
- 飞机权重和完整MIT/Apache/第三方声明在两平台构建前检查并随包复制；许可文本的字节数与哈希记录在Licenses/checksums.json。

应用运行时读取随包资源，本地识别与编辑，不联网下载模型或上传照片。开发构建首次下载依赖与用户运行软件应区别说明。

## macOS

需要支持macOS14目标的Xcode/Swift工具链，使用完整Xcode的Developer目录。原生核心、界面和系统编解码不依赖Qt。

```zsh
swift test
python3 -m unittest discover -s scripts/tests
UNIVERSAL=1 zsh scripts/build_app.sh
zsh scripts/make_dmg.sh
```

输出`dist/BirdLock.app`和`dist/BirdLock-1.4.0.dmg`及`.sha256`。可用`APP_OUTPUT`指定独立候选目录；不要覆盖已验收包。打包会生成随包HTML/PDF说明并复制当前协议、许可、模型、音效和赞赏图片，然后签名。

当前为临时签名，不等于Developer ID签名、Apple公证或Gatekeeper信任。`SIGN_ID`只提供签名入口；正式分发与公证按维护者后续安排进行。

## Windows

目标为Python3.12 x64，安装`windows/requirements.txt`与PyInstaller；完整步骤见[Windows开发说明](../windows/README.md)。

```powershell
python windows/build_windows.py
```

输出`windows/dist/BirdLock/`及`windows/dist/BirdLock-1.4.0-Windows-x64.zip`。构建按清单准备飞机模型、FFmpeg、文档与版本资源。CI在构建准备好FFmpeg后运行完整音频单元测试，再执行源码与冻结程序自检，避免未安装FFmpeg就运行实际混音测试。

Parallels Windows ARM中的x64模拟可用于回归，不能代替实体NVIDIA/AMD/Intel显卡验证。DirectML、OpenCL、硬件编码不可用时允许已有CPU/软件编码回退，并保留诊断信息。

## Mac传输与资源密封

签名后修改、增删包内文件，或传输/解包损坏包结构及执行权限，可能导致启动失败。完整DMG字节不变时，内部资源不应因经过聊天/网盘传输而被直接改写。原UTF-8启动报错在本地未复现，不能仅凭提示确认资源密封是唯一根因。

1. 模型、文档、Info.plist等全部放齐后再签名；偏好/缓存留在应用包外，签名后不编辑包内容。
2. 传输完整只读DMG；不要拆开.app或网盘在线解包后逐文件下载。使用ZIP时也需保留Mac包结构。
3. `make_dmg.sh`和既有`make_release.sh`调用[分发验证器](../scripts/verify_mac_artifact.py)：检查最终DMG/ZIP、包内签名、复制到临时安装目录后的签名和启动权限，并确认验证前后分发文件SHA256不变。失败中止，不重签掩盖错误。
4. 分发附SHA256SUMS；下载后先核对哈希再安装。哈希不符重新取得原包；一致仍失败时记录具体错误、系统版本、芯片与启动方式。
5. 验签完整不代表已公证，清除隔离标记不能修复签名损坏。检查器不启动应用、不重签、不清除隔离标记，自动卸载自己挂载的测试镜像。

参考：[Apple TN2206](https://developer.apple.com/library/archive/technotes/tn2206/)、[Apple分发打包说明](https://developer.apple.com/documentation/xcode/packaging-mac-software-for-distribution)。本地1.4通用DMG挂载及模拟复制安装验签通过，未实际验证所有聊天/网盘传输方式或受影响设备。

## 统一GitHub Actions

入口[release.yml](../.github/workflows/release.yml)，复用[windows.yml](../.github/workflows/windows.yml)。

| 触发 | 行为 |
|---|---|
| 推送普通分支（包括main） | 不触发这两个打包workflow，不创建Release |
| 手动运行统一workflow | 版本校验、双平台构建/测试、同提交源码、校验汇总；只生成Actions产物 |
| 经批准推送匹配的`v*`标签 | 同上，成功后创建含双平台/源码/SHA256SUMS的同一个Release草稿；测试标签标prerelease |
| 单独手动运行Windows workflow | Windows构建、测试与产物，不直接发布Release |

三类主要文件必须齐全、非空且版本一致，才能汇总：`BirdLock-<版本>.dmg`、`BirdLock-<版本>-Windows-x64.zip`、`BirdLock-<版本>-source.zip`。任一构建失败不会创建不完整Release；已有同名Release时跳过草稿创建，不修改其标记或覆盖资产。草稿仍需检查后明确发布；安装包应保留对应源码及SHA256。

本次发布复用已完成双平台本地验证的1.4.0安装包，复制到发布暂存目录后再次核对原始SHA256、Windows ZIP完整性和Mac DMG挂载/复制安装签名；不修改包内资源、签名或构建时文档。公开源码ZIP由发布标签所指提交生成，后续改动仅为发布文档及workflow已有Release保护，应用代码/有效资源与受测版本一致。校验文件覆盖这三个正式资产。

workflow已做本地静态/嵌入脚本验证；发布现有本地受测包不代表云端已重建成功。云端权限、SDK和打包结果须以各次实际运行记录为准，不能用文件存在代替成功记录。

## 回归与维护

- Swift核心、Windows核心及脚本资源/分发测试覆盖算法、编辑、混音与包装边界。
- 内部`--project-regression`覆盖12张以上照片、分组排序/缓存/特写、音乐对齐、相机菜单、赞赏页、实际视频及短音频静音。
- `--subject-regression`覆盖主体切换/取消恢复、独立设置重启、两组飞机、机头/机身与导出。
- 项目和主体回归必须指定一次性`BIRDLOCK_DATA`，普通用户无需运行；测试只读照片，不写回EXIF。
- 虚拟机集中测试，结束后关闭本任务程序和孤立控制台，恢复测试前运行状态；不按程序名无差别终止用户程序。
- 每次改动同步更新使用说明、版本记录、许可/音效资源清单与[验收清单](整批功能验收清单.md)。公开提交不包括偏好、测试照片、缓存、诊断日志、私人路径和本地维护记录；本地回滚点和旧包保留。

1.4已完成本地Swift44项、Mac/Win各62项、资源11项及原生/Qt/Windows冻结成品验证；Windows80次布局、H264/HEVC和20轮短音频通过。实体Intel/x64显卡、低内存、Mac历史启动错误及飞机复杂/真实连拍精度仍待补测。
