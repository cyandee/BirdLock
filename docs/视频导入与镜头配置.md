# 视频导入、原声与增稳（1.9.0）

本文对应1.9.0。视频导入与增稳仍为实验功能。原视频只读，视频、声音与运动数据都在本机处理。

## 使用

1. 在顶部选择「鸟类」或「飞机（试验）」。打开「文件 → 导入视频（实验）…」，也可以单独拖入一个视频；视频拖入会进入视频导入面板。
2. 设置起点、时长和采样帧率。默认先取 10 秒、最多 30 fps；每次上限 120 秒 / 3600 帧，采样范围 1–60 fps，低于设定帧率的源视频按源帧率导入。建议先用 5–10 秒片段检查效果。面板会显示实际起止、帧数和采样帧率；片尾自动截到原视频结尾，源帧率较低时使用源帧率。超出片段或帧数限制时先修正参数再导入。
3. 查看自动识别的机身与镜头。在「镜头配置（可选）」的同一个框内输入机身、镜头、焦距或模式，然后选择匹配项；回车确认、Esc 取消搜索，清空或「清除配置」可停用校正。输入搜索词不会直接套用配置。经核对过的组合只有匹配条件满足且结果唯一时才自动选中；其余数据库条目需手动核对模式；候选不确定时手动确认，也可点「导入镜头配置…」选择 Gyroflow JSON 或索尼 XML。没有对应配置时点「查找配置」。镜头校正为可选项，已经在机内校正的视频通常无需再次校正。
4. 点「导入并分析」。视频有可解码音轨时，会自动添加「视频原声」；不必再手动提取为背景音乐。
5. 在「画面 → 视频防抖」选择方法、取景、强度、平滑时间与自动裁切。选择「主体锁定」时，再在「构图」中选择鸟眼或鸟头中心；飞机模式使用机头。选择「平滑相机运动」时，以相机画面为取景基准。
6. 检查预览、识别与声音，必要时逐帧手动修正，再导出 MP4 / MOV。默认文件名来自原视频，默认位置为原视频所在文件夹；文件夹不可用时回到用户文档或主目录。鸟类后缀为「鸟眼锁定」，飞机为「机头锁定」。建议先用短片段对比启用/关闭防抖，确认画面边缘与目标位置后再处理长片段。

Mac 使用系统 AVFoundation 解码，Windows 使用随包 FFmpeg。入口接受 MP4、MOV、M4V、AVI、MKV，实际可读性取决于系统/后端的编码支持，推荐常规 SDR H.264 / HEVC 的 MP4 / MOV。无法解码会报错并清理这次未完成的缓存。提取视频帧阶段失败或取消时保留之前已完成的项目。

## 原声随剪辑

「视频原声」按最终成片时间线排列，随裁剪、排除、变速、倒放、往返和重复调整。特写定格期间原声静音，结束后按后续画面继续；无音轨的视频不会额外生成原声轨。

在「音效与多轨」中可以静音、调整音量和淡入淡出，或移除原声。原声的起点、长度和循环由画面剪辑管理。变速通过重采样实现，音高也随速度变化。背景音乐和其他声音仍可单独添加；导出 GIF 或图片序列时没有音轨。

## 画面页的视频防抖

导入分析时会测量相邻视频帧的相机运动，并尝试读取原片内的陀螺仪数据。随后在「画面 → 视频防抖」调整：

| 设置 | 用法 |
|---|---|
| 启用防抖 | 对比原有取景与防抖后的效果 |
| 方法：自动融合 | 有可用陀螺仪时结合陀螺仪与图像运动；没有时使用图像防抖 |
| 方法：图像防抖 | 根据画面测得的平移、旋转和尺度变化平滑相机轨迹，不需要陀螺仪 |
| 方法：陀螺仪 | 用角速度积分和平滑姿态计算画面校正；没有足够采样时仍会显示实际使用的图像防抖方法 |
| 取景：主体锁定 | 在校正相机运动后沿用鸟眼、鸟头或机头的构图与跟随设置 |
| 取景：平滑相机运动 | 以画面中心为基准，保留平滑的相机运镜，不把主体固定在锁定点 |
| 防抖强度、平滑时间 | 强度越高校正越多；平滑时间越长，运镜变化越缓，也可能需要更多裁切 |
| 自动裁切边缘、最大附加裁切 | 可选 1–8×；允许更大裁切，能保留更强的校正。达到限制时会收小校正幅度；8× 表示每边线性视野最多缩小到约 1/8，清晰度与取景范围会明显下降 |
| 固定裁切 | 全片采用所需的最大附加裁切，减少防抖缩放呼吸；关闭后可随帧缓慢调整。主体锁定且锁定大小时会自动保持固定裁切，此时开关保持选中并禁用 |
| 强力防抖预设 | 将强度设为 100%、平滑时间设为 1.5 秒、最大附加裁切设为 6×，开启自动裁切和固定裁切；仍可逐项调整 |

方法旁的问号可悬浮查看图像防抖、陀螺仪与自动融合各自适用条件、优势与局限。平滑时间最高 10 秒；长平滑时间通常需要更大裁切。

选择主体锁定及「锁定主体大小」时，会用全局图像尺度变化和稳健的头部尺寸曲线，抑制抖动、检测框跳动和逐帧裁切造成的大小波动。小幅尺寸噪声会被忽略，持续变化会缓慢跟随，因此真实靠近、远离或突然变焦可能有跟随延迟；不等于恢复失焦、运动模糊或真实缺失的细节。

调整这些设置会重算当前取景，不需要重新提取视频帧。仍需检查主体、背景和边缘是否符合预期。目标过小、模糊、遮挡、切镜、背景缺少纹理或大幅视差都可能影响分析；主体锁定也不保证地平线完全稳定。

## 陀螺仪导入与同步

在「画面 → 视频防抖」点「导入陀螺仪…」，可以选择 GCSV 记录、包含原始 IMU 数据或本地源引用的 Gyroflow 工程，以及确实记录了陀螺仪的相机原片。普通 CSV 必须符合支持的运动数据格式，文件扩展名本身不能证明包含陀螺仪。

开启「自动同步陀螺仪」后，软件比较画面运动与角速度变化，估计时间偏移。查看状态中的实际方法、同步偏移和提示；自动同步未通过时，不能把导入成功当作对齐成功。可用「重新同步」重算，或在「手动微调」中以毫秒调整。正值表示同一视频时刻读取更晚的陀螺仪样本。开启自动同步时，该字段是叠加在自动结果上的附加偏移；关闭自动同步时，它就是总时间偏移。

从 Gyroflow 工程读取运动数据不等于恢复整个工程；仍需核对当前片段、传感器方向与时间对齐。没有真实角速度采样或选择纯图像防抖时，同步和偏移控件不可用；仍可导入真实记录。没有真实角速度采样时会显示「无陀螺仪记录」，使用图像防抖，不会根据镜头型号生成虚拟采样。

用户提供的 `C0320.MP4` 已读出 840 帧元数据，但陀螺仪采样为 0；对应 `C0320M01.XML` 可识别 Sony ILCE-1M2 与 FE 600mm F4 GM OSS，不能据此声称已完成该原片的陀螺仪防抖。

该静止鸟样例在 Python 路径完成了 211 帧视觉防抖对比：在 1280 像素宽的对比画面上，以独立相位相关测量 210 对相邻帧，位移 RMS 从 2.7796 像素降至 0.5050 像素，最大额外裁切为 1.0847×，原片未改动。原生 Mac 路径复用同一组 JPEG 的独立测量为 2.7803 → 0.8184 像素，下降约 70.6%，最大额外裁切 1.1046×；实际 AVFoundation 导入、原声和 MP4 导出也已完成本地回归。这只是这个样例的测量结果，不代表飞行鸟类、飞机或其他镜头的稳定效果。

## 自动识别与镜头配置

离线内置 383 份来自 Gyroflow 镜头库的真实配置，保留原始文件、SHA256、来源和 CC0 许可。新增 375 份覆盖 Sony、DJI、GoPro、Canon、Nikon、Panasonic、Fujifilm、Blackmagic、Insta360、Olympus；搜索可输入「索尼 FX3」「Nikon 4K」「16-35」等多个词。机身、镜头或拍摄模式不同的配置不能互相代替。

原有 8 份已核对匹配条件的组合如下，其余新增条目需要用户手动选择并核对拍摄模式：

| 相机与镜头 | 标定模式 |
|---|---|
| Sony A7 IV + Sigma 28–70mm F2.8 @28mm | 4K25 |
| Sony FX3 + FE 24mm F1.4 GM | 4K25 |
| Sony FX3 + FE 16–35mm F2.8 GM II @16mm | 4K59.94 |
| Sony α6700 + E PZ 10–20mm F4 G @20mm | 4K59.94 |
| GoPro HERO11 Black Wide | 4K119.88 16:9，HyperSmooth 关闭 |
| GoPro HERO11 Black Wide | 5.3K29.97 4:3，HyperSmooth 关闭 |
| DJI Mini 3 Pro | 1080p29.97 |
| DJI Osmo Action 3，155°超广角 | 4K59.94 |

自动匹配会核对机身、镜头、焦距、视频尺寸、帧率及已知拍摄模式。变焦镜头缺少焦距、存在多个候选、尺寸变化或已知裁切/防抖模式不兼容时，不自动套用，需要手动确认。没有对应组合时，点「查找配置」进入 [Gyroflow 镜头库](https://github.com/gyroflow/lens_profiles) 搜索机身、镜头、焦距和模式，导出对应 JSON；仍没有时，参考[官方镜头标定教程](https://docs.gyroflow.xyz/app/getting-started/lens-calibration)创建配置。

索尼同目录的 `片名M01.XML` 或 `片名.XML` 会自动读取，也可以从「导入镜头配置…」手动选择。XML 用于读取机身、镜头和拍摄模式，并据此匹配内置组合；普通 Sony XML 里的身份信息不是光学标定，也不一定有陀螺仪。该 XML 没有的畸变系数或运动样本不会被补造。内置库当前没有 ILCE-1M2 + FE 600mm F4 的对应标定，不应改选其他机身或镜头来代替。

### 静态 JSON 范围

支持 Gyroflow JSON 中的静态 `calib_dimension`、`fisheye_params.camera_matrix` 和 `distortion_coeffs`：

| 模型 | 系数 |
|---|---|
| `opencv_fisheye`（未注明模型时的默认值） | 4 个鱼眼系数 |
| `opencv_standard` | 4 / 5 / 8 个常规 OpenCV 系数 |

同宽高比的分辨率会等比缩放内参。镜头、焦距、对焦状态、传感器裁切区域和机内防抖模式也必须匹配；仅宽高比相同不能保证配置准确。非等比拉伸、数字镜头（如 SuperView）、变焦插值、自定义畸变模型和不支持的系数会拒绝导入。

校正在识别之前完成，预览、手动修正和导出共用校正后坐标。输出视野可能改变，部分配置会在边缘产生黑区，需收紧取景。换镜头配置需重新导入，使用独立的识别与编辑缓存。内置库离线随包提供，运行时不会自动下载整个镜头库，也不保证识别所有相机组合。

## 性能与资源

分析与导出并行度根据 CPU 核数和估计的同时在用图像内存调整，保留系统余量，避免高分辨率片段在低内存设备上无限排队。内置镜头清单校验结果在当前进程缓存，搜索无需反复读取数百个 JSON。

Mac 在至少 24 GiB 内存、8 核且关闭低电量模式时使用两个独立 Core ML 预测实例；其他设备保留一个实例，低电量模式进一步限制并行度。常规视频渲染采用有上限的并行预取及按序写出；AI 光流仍按单工作队列执行。Windows 提高可用图像任务的并行上限并按分辨率限制缓存，DirectML 同一推理会话仍串行调用，显卡或硬件编码不可用时保留回退路径。

本机同一 C0320 片段的 48 帧鸟类分析，单预测实例约 1.96 秒、双实例约 1.79 秒，约快 8.7%；211 帧 4K 导出约 2.94 秒，两种并行度基本相同，瓶颈仍可能在编码器。该小样本不代表其他电脑或所有流程的提速，资源占用率也不会始终满载。

## 增稳与限制

本地候选已验证 Mac 原生与 Python 增稳核心、真实原声、可控时间偏移同步以及 C0320 视觉效果。Mac 辅助进程的 ARM 与 Intel 架构均在本机运行通过。Windows 本轮按用户决定不做运行验证，由用户在实体电脑测试。该候选保留已核验的 1.6.0 Windows 运行库，重新编入 1.9.0 程序、辅助组件和资源，已检查归档、源码与版本一致性；这不等于 Windows 成品运行通过，也不代表所有相机均已验收。

本版不承诺完整 Gyroflow 工程兼容、滚动快门逐行校正、动态焦距/镜头呼吸补偿或 HDR 工作流。HDR PQ/HLG 会拒绝导入，请先转为 SDR。读取到快门读出时间或镜头名称，也不等于已经应用对应校正。

按固定采样时钟生成 JPEG 97 质量帧缓存，再沿用现有分析和导出流程。可变帧率视频也按该时钟采样；低采样帧率会减少运动细节，视频的原始时间戳/色深和压缩数据不会无损保留。8 位 SDR 缓存会占用磁盘，空间不足时导入停止。

缓存位于 Mac 的 `~/Library/Caches/BirdLock/video-imports`，Windows 数据目录的 `cache/video-imports`。同一原文件与导入参数可复用缓存和编辑；修改源文件、片段、帧率或镜头 JSON 会形成另一缓存。原声和运动分析也使用本地缓存。使用「文件 → 保存工程」保存 `.birdlock` 后可继续编辑；视频导出成功后可选择保存工程并清理过程文件。缓存管理默认上限20GB，优先清理可重建的JPEG/PCM，保留编辑与运动记录，当前任务受保护。工程引用原片，需保留素材。详细步骤见[工程与缓存管理](工程与缓存管理.md)。测试程序请使用一次性 `BIRDLOCK_CACHE`（Mac）或 `BIRDLOCK_DATA`（Windows）。

## 特写音效

添加的内置相机连拍音效在实际成片的特写时段自动静音，特写结束后按原时间轴恢复；特写的单次音效与背景音乐保留。倒放、往返、重复、裁剪和排除都按最终时间线计算，不改保存的原音轨。关闭特写单拍声时，特写期间仍暂停连拍声。很短的特写会把单拍声截到特写结束，避免尾声叠到恢复的连拍声。
