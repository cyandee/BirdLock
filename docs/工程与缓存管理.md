# 工程与缓存管理

适用于 BirdLock 1.9.0 本地测试候选。Mac 与 Windows 使用相同的 `.birdlock` 工程格式。

## 保存与继续编辑

导入并完成识别后，选择「文件 → 保存工程」。第一次保存需要指定位置；「另存为工程」可以保留另一份编辑方案。Mac 快捷键为 ⌘S / ⇧⌘S，Windows 为 Ctrl+S / Ctrl+Shift+S。

工程保存当前素材、分组与合并顺序、识别结果、手动定位、排除帧、特写、裁剪、构图、画面、防抖、输出设置、音轨、水印和当前预览位置。关闭、退出或更换素材时，如果编辑尚未保存，会询问保存；取消保存会保留当前工作。

下次选择「文件 → 打开工程」（Mac ⌘O，Windows Ctrl+O），或拖入 `.birdlock` 文件。Mac 安装版也可以从访达打开。继续编辑使用已保存的识别结果，不必重新识别主体。照片导入快捷键调整为 Mac ⌥⌘O、Windows Ctrl+Alt+O。

**工程引用素材，不复制原片。** 请同时保留原视频、照片、自行添加的音乐与水印文件。建议工程与素材一起归档，移动时保持相对目录结构。找不到原片时会提示选择素材文件夹重新定位；缺少可选音乐或水印时会提醒重新选择。工程不能替代素材备份，导出视频也不能恢复完整编辑。

1.9 之前导入的视频缓存没有完整重建参数，需重新导入一次视频后再保存工程。工程请保存在缓存目录之外。两个平台均支持该格式，但本次 Windows 成品运行由用户在实体电脑测试；这里的共享格式验证是在 Mac 的原生与 Python/Qt 实现之间完成。

## 视频导出后的清理

视频导出成功后，可以选择：

- **保留过程文件**：继续当前编辑，不清理。
- **保存工程并清理**：先保存工程；保存成功后关闭当前工作，清理本次视频可重建的 JPEG、原声 PCM 和缩略图。取消或保存失败时不清理。

原片、已导出视频、工程、编辑记录和运动数据会保留。下次打开工程时，软件依据原片与保存的采样/镜头参数恢复过程文件，沿用识别结果与编辑；恢复需要一定时间。导出失败或取消时不会询问清理，导出图片/GIF 也不触发该提示。

## 缓存上限

打开「文件 → 缓存管理」设置上限，默认 **20 GB**；设置为 **0** 表示不限制。也可关闭视频导出后的清理询问，或手动「清理未使用的过程文件」。设置会在下次启动时沿用。

软件优先清理较久未使用、确认可由现存原片重建的文件。当前工作和进行中的导入、识别、恢复、导出受保护；原片、工程、导出成品及编辑/运动 JSON 不属于自动清理范围。旧版缺少重建参数的缓存、原片丢失的缓存也会保留。因此受保护内容可能使实际占用超过上限，软件会提示；关闭工程后可再清理。上限控制应用缓存，不包含原片、导出视频和其他用户文件。

Mac 默认缓存位于 `~/Library/Caches/BirdLock`。Windows 优先使用程序目录下 `data/cache`，程序目录不可写时回退到 `%LOCALAPPDATA%/BirdLock` 的数据目录。请通过软件内的缓存管理清理；手动删除整个数据目录仍可能丢失未保存的编辑与偏好。
